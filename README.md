# Senim — аудармаға дейін алаяқтықты анықтау

FINTECH CASE үшін MVP. Клиент «банктің қауіпсіздік қызметі» деген алаяқтың айтуымен ақшаны **өзі**
аударады, сондықтан әдеттегі антифрод оны көрмейді. Senim аударманы бұғаттамайды — тәуекел жоғары
болса, оны бір сәтке тоқтатып, клиентпен қысқа диалог жүргізеді.

**Демо:** https://baibek.github.io/safepause/ · **Кейс талаптары мен нәтижелер:** [docs/CASE_MAP.md](docs/CASE_MAP.md) ·
**BCC-ке енгізу:** [docs/BCC_INTEGRATION.md](docs/BCC_INTEGRATION.md)

## Басқалардан айырмашылығы

Senim алаяқты **қоңырау кезінде естиді**. Сөйлеу құрылғының ішінде мәтінге айналады (Vosk, қазақ және орыс,
интернетсіз), ал детектор алаяқ сценарийінің сатыларын (таныстыру → қорқыту → сұрау → оқшаулау) санайды.
Қоңырау алаяқ деп танылса, келесі 60 минутта банк қосымшасындағы кез келген аударым тексеруге түседі.

## Не шынайы, не симуляция

| Бөлік | Демода | Банкте |
|---|---|---|
| Сөйлеуді тану, сценарий детекторы | Шынайы: Android-та және сайтта (браузердегі Vosk) | Сол модуль BCC қосымшасының ішінде |
| Аударым скорингі, түсіндірме, диалог, кідірту | Шынайы логика, синтетикалық деректер | BCC тарихымен қайта үйрету |
| Дроп-желі графы | Шынайы алгоритм, синтетикалық транзакциялар | Антифрод растаған шоттар |
| Демо-қоңыраулар | Piper дауыстарымен жазылған 100 диалог | — |
| Қамқоршыға хабар | Демо экранында | Push немесе SMS |

## Senim Сақшы: тәуекелге негізделген динамикалық тексеру

Senim-нің жалғасы. Әр аударымға 0–100 балл есептеледі. Тексеру деңгейі осы балға байланысты, ал шекті мәндер
мен салмақтар кодта емес, бір конфигурация файлында тұр: [`shared/risk_policy.json`](shared/risk_policy.json).

| Балл | Деңгей | Не болады |
|---|---|---|
| 0–29 | `pass` | Өтеді. Ерекшелігі: жаңа алушыға алғашқы ірі аударым (200 000 ₸-ден) 30 минут, жаңа құрылғыдан алынған несие 24 сағат күтеді |
| 30–59 | `warn` | Банктің растау қоңырауы (1 — өзім, 2 — мен емес). Қазір қоңырау жүріп тұрса не қашықтан басқару қосулы болса, оның орнына сұрақтар қойылады |
| 60–79 | `cool` | Сұрақтар және салқындату кезеңі (60 минут). Клиент кез келген уақытта бас тарта алады |
| 80+ | `escalate` | Сұрақтардан кейін сенімді адамның растауы керек, ал ол болмаса, аналитиктің шешімі. 24 сағатта жауап болмаса, аударым жасалмайды |

**Сигналдар** (салмағы `risk_policy.json`-да): Call Guard анықтаған алаяқ қоңырауы, алушы дроппер тізімінде, жаңа
құрылғыдан алынған несие бірден аударылып жатыр, қашықтан басқару, сома әдеттегіден 3 / 10 есе көп, басқа банкке ірі
сома, алушыға соңғы сағатта көп адамнан ақша келген, аты шот иесімен сәйкес емес / ішінара сәйкес, белсенді қоңырау,
бейтаныс нөмір, жаңа құрылғы, root / эмулятор, жаңа алушы, түнгі уақыт, VPN және XGBoost моделінің бағасы. Әр балл
түсіндіріледі: клиент те, аналитик те «қай сигнал неше балл қосты» деп көреді.

### Архитектура

```
 Клиент қосымшасы ─┐                         ┌─ shared/risk_policy.json  (салмақтар, шектер)
 Аналитик / пульт ─┼─► POST /api/transfer/check ─► policy.evaluate() ─► pass / warn / cool / escalate
                   │        │                    └─ shared/policy_cases.json (Python мен JS-ке ортақ тесттер)
                   │        ├─ backend/saqshy.py: сейф, сенімді адам, Call Status, дроппер тізімі, audit log
                   │        └─ XGBoost + SHAP: модельдің бағасы бір сигнал ретінде
                   └─ GitHub Pages: сол логиканың браузердегі көшірмесі (frontend/src/virtual/)
```

### Клиентке арналған қорғаныс

| Функция | Қайда | API |
|---|---|---|
| «Бұл шынымен банк пе?» (Call Status) | Қорғаныс → Тексеру. Қызметкер сессиясы аналитик бетіндегі пульттен ашылады | `GET /api/callstatus/{id}`, `POST /api/callstatus/start`, `/end` |
| Сенімді адам: шақыру → келісім → 80+ операцияны растау; басқа банктің клиентіне SMS | Қорғаныс → Сенімді адам | `POST /api/protect/trusted/invite`, `/accept`, `/remove`, `POST /api/guardian/respond` |
| Сейф: құлыпталған ақшаны аудару мүмкін емес, ашу тек банкомат / бөлімше + биометрия | Қорғаныс → Сейф; ашу — пульттегі «Банкомат» батырмасы | `POST /api/protect/lock`, `/unlock` |
| Алушыны тексеру: аты шот иесімен толық / ішінара / сәйкес емес, дроппер тізімі | Аударым формасы, жаңа алушы | `POST /api/recipient/check` |
| Салқындату кезеңі | Аударым нәтижесі | `transfer/check` → `action: "cooling"` |
| Қауіпсіздік индексі (passkey 35, сенімді адам 35, сейф 30) | Қорғаныс | `GET /api/protect/{id}` |

### Банк жағы

Аналитиктің қосымшасында кезектегі аударымды ашып, оны өткізуге, бас тартуға немесе сенімді адамға жіберуге болады.
Шотты дроппер тізіміне қосса, сол шотқа келесі аударым бірден 80+ балл алады. Метрикалар: растау күтетіндер,
жалған кідіріс үлесі, сенімді адамы / сейфі / passkey-і бар клиенттер үлесі. Барлық шешім audit log-қа жазылады
(`GET /api/audit`): кім, қандай рөлде, қашан, неге. Телефон нөмірлері журналда маскаланады.

### Демо-сценарийлер (автоматты тесттер: `backend/test_scenarios.py` және `npm run test:engine`)

1. **Қоңырау кезінде жаңа алушыға ірі сома.** «Банк қауіпсіздік қызметі» дайын сценарийі → Жалғастыру → Ескертуді көру → «Бәрібір жалғастыру» → сұрақтарға «Жоқ» → «Сенімді адамның растауы күтілуде». Қорғаныс → Сенімді адамның телефоны → «Тоқтату». Ақша кетпейді.
2. **Call Status.** Қорғаныс → Тексеру: «Банк қазір сізбен сөйлеспей тұр». Аналитик бетіндегі пульттен «Клиентке қоңырау шалу» → қайтадан Тексеру: қызметкердің аты мен ID-і шығады.
3. **Сейф.** Айгүлдің 400 000 ₸-сі сейфте. Сол ақшаны қамтитын сома аударылса, «Бұл сома сейфте құлыпталған» деген хабар шығады. Ашу тек пульттегі «Банкомат» арқылы.
4. **Таныс алушыға кәдімгі аударым.** «Қызына әдеттегі аударма» → кедергісіз өтеді.
5. **«Тексеріп бер».** Тексеру табына «Kaspi-ден ұтыс! … http://…» мәтінін қойыңыз → «Алаяқтық» және себептері.
6. **Дроппер тізімі.** Аналитик → Желі → шотты басу → «Дроппер тізіміне қосу». Сол шотқа келесі аударым 80+ балл алады.

### Іске қосу және баптау

- Сервер: `./run.sh` (кілттер мен баптаулар тек `.env` файлынан алынады, үлгісі — [`.env.example`](.env.example)).
- Жасанды деректер: [`shared/seed_saqshy.json`](shared/seed_saqshy.json) — екі демо-клиенттің және тағы 13 клиенттің қорғаныс баптаулары, шот иелерінің аттары, банк қызметкерлері. «Демоны тазарту» батырмасы бәрін осы күйге қайтарады.
- Ережелерді баптау: `shared/risk_policy.json`-дағы `points`, `thresholds`, `cooling`, `trusted_timeout_hours`. Өзгерткеннен кейін `shared/policy_cases.json`-ды жаңартып, `pytest` пен `node --test frontend/src/virtual/policy.test.mjs` іске қосыңыз.

### Шектеулер

- Бұл демо, банктің нақты жүйесі емес. Барлық клиенттер, шоттар мен қызметкерлер жасанды.
- Күй жадта сақталады, сервер қайта қосылғанда seed күйіне қайтады.
- Телефония (Call Status), SMS, банкомат пен биометрия — симуляция.
- GitHub Pages нұсқасында бүкіл «сервер» пайдаланушының браузерінде жұмыс істейді, сондықтан ол жерде рөлдер мен кіру тек демонстрация. Рөлдер, rate limit және CSRF Python серверіне арналған келесі кезеңде қосылады.
- Passkey (FIDO2) индексте көрсетілген, бірақ әлі қосылмаған — келесі кезең.

## Не істейді

| Тарап | Мүмкіндік |
|---|---|
| Клиент | Әр аударманы нақты уақытта бағалау → тәуекел жоғары болса AI-диалог (қазақша / орысша) → аударма **өтеді**, **кейінге қалады** немесе **тоқтатылады** |
| Клиент | Банктің растау қоңырауы: әдеттен тыс, күдікті немесе басқа банкке ірі аударымда банк роботы қоңырау шалып ескерту оқиды; клиент 1-ді басса аударым жіберіледі, 2-ні басса бұғатталады |
| Клиент | «Қамқоршы» режимі: қарт клиенттің ірі күдікті аудармасы туралы сенімді туысына хабар барады, ол растай не тоқтата алады |
| Клиент | Хабарлама тексеру: күдікті SMS / WhatsApp мәтінін қойса, алаяқтық белгілері қарапайым тілмен түсіндіріледі (LLM + ережелер) |
| Банк | Аналитик дашборды: аудармалар легі, әр шешімнің түсіндірмесі (SHAP үлестері), клиентпен диалог |
| Банк | Дроп-желілер графы: ақша кіріп, бірнеше минутта шығып кететін шоттар тізбегі |

Екі бөлік байланысты: графта дроп деп табылған шотқа аударма жасалса, клиент жағындағы тәуекел өседі.

## Іске қосу

```bash
./run.sh
```

Сосын браузерде `http://localhost:8000` ашыңыз. LLM мәтіндері үшін `ANTHROPIC_API_KEY` орнатыңыз;
кілт болмаса, диалог дайын үлгі мәтіндермен жұмыс істейді (шешім логикасы өзгермейді).

Әзірлеу режимі: `cd backend && uvicorn main:app --reload --port 8000` және `cd frontend && npm run dev`.

### Виртуалды нұсқа (серверсіз)

```bash
cd frontend && npm run build:virtual
```

`frontend/dist-virtual/` ішінде бір бет пен `app.js` шығады: модель (XGBoost ағаштары + дәл TreeSHAP),
диалог логикасы мен граф толығымен браузерде жұмыс істейді. `node src/virtual/check.mjs` JS-порттың
XGBoost-пен сәйкестігін тексереді. Модельді қайта үйреткен соң `python backend/export_virtual.py` іске қосыңыз.

## Демо сценарийі (2 минут)

1. **«Банк қауіпсіздік қызметі» қоңырау шалды** → «Аудару». Модель 100% тәуекел береді, диалог басталады.
   «Иә» деп жауап берсеңіз — аударма бірден тоқтатылады, қамқоршыға хабар барады.
2. Сол сценарийде бәріне «дұрыс» жауап беріңіз (алаяқ үйретіп қойған жағдай) — аударма бәрібір
   60 минутқа кейінге қалады, қамқоршы оны тоқтата алады.
3. **Қызына әдеттегі аударма** — ешқандай кідіріссіз өтеді.
4. **Аналитик дашборды** — осы аудармалар лекте «демо» белгісімен тұр; алушы шот графтағы №1 желіде.

## Қалай жұмыс істейді

- `backend/train.py` — деректерді генерациялайды және XGBoost моделін үйретеді. 14 белгі: сома,
  әдеттегі сомаға қатынасы, жаңа алушы, уақыт, телефон қоңырауы, бейтаныс нөмір, қашықтан басқару
  қолданбасы, әрекет қарқыны, алушы шотының жасы мен дроп-баллы және т.б.
- `backend/main.py` — FastAPI. Тәуекел < 25% → өтеді; одан жоғары → диалог. Шешімді ережелер қабылдайды,
  LLM тек мәтінді қарапайым тілмен жазады және еркін жауапты «иә / жоқ» деп түсінеді.
- `backend/graph.py` — NetworkX. Шот белгілері: транзит үлесі, ақшаның шотта тұру уақыты, жіберушілер
  саны, шот жасы → дроп-балл → байланысқан компоненттер = желілер.
- `backend/llm.py` — Claude API (`claude-opus-5-5`, `SAFEPAUSE_LLM_MODEL` арқылы өзгертуге болады).
- `shared/message_rules.json` — хабарлама тексерудің ережелері; backend пен браузер бір файлды қолданады.
  LLM үкімі ережелер тапқаннан төмен түсе алмайды.
- `frontend/src/virtual/` — backend-тің браузердегі порты (виртуалды нұсқа үшін).
- `frontend/` — React + Vite, граф үшін vis-network.

## Шектеулер (ашық айтамыз)

- **Деректер синтетикалық.** PaySim / IEEE-CIS датасеттерінде қоңырау мен құрылғы белгілері жоқ, сондықтан
  олар сценарийге сай үлестірімдермен генерацияланды. ROC-AUC 0.96 — модельдің нақты сапасы емес,
  пайплайнның жұмыс істейтінінің дәлелі. Графтағы 100% дәлдік те сол себепті.
- Қоңырау мен AnyDesk белгілері демода қолмен қосылады; нақты қосымшада оларды мобильді SDK жинайды.
- Сақтау жадта (in-memory), авторизация жоқ. Кейінге қалдыру таймері көрсетіледі, бірақ іс жүзінде санамайды.
- Граф бөлігі — графтық белгілер + эвристика; GNN келесі қадам.
