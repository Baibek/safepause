# SafePause в мобильном приложении банка — как встроить

Документ для команды мобильного приложения и антифрода банка. Всё ниже уже реализовано в репозитории и
проверено тестами; что ещё не проверено — в конце.

## Что получает банк

| Проблема | Что делает SafePause | Где в коде |
|---|---|---|
| Клиент сам переводит деньги под диктовку «службы безопасности» — классический антифрод видит обычный перевод | Слушает звонок **на телефоне клиента** (с его согласия), узнаёт сценарий мошенника и предупреждает во время разговора | `android/` (Call Guard) |
| Банк не знает, что клиента прямо сейчас обрабатывают по телефону | После такого звонка приложение передаёт в проверку перевода **один числовой признак** — сколько минут назад был мошеннический звонок | `SafePauseSdk.transferSignals()` → `signals.scam_call_minutes` |
| Блокировка перевода злит клиента, пропуск — стоит денег | Перевод не блокируется, а **ставится на паузу** с коротким AI-диалогом; итог — пропустить, отложить или отменить | `backend/main.py` `/api/transfer/check`, `/api/dialog/answer` |
| Пожилые клиенты | Режим «Опекун»: доверенный родственник получает уведомление и может остановить отложенный перевод | `/api/guardian/*` |
| Деньги уходят через дроп-счета | Граф переводов находит цепочки «пришло — ушло за минуты», признак попадает в скоринг получателя | `backend/graph.py` |

## Поток данных

```
Телефон клиента                                   Сервер банка
───────────────                                   ────────────
звонок ─▶ Call Guard (Vosk, правила; офлайн)
            │ уровень риска HIGH
            ▼
       CallRecord (локально; текст разговора по умолчанию не хранится)
            │
перевод в приложении ─▶ SafePauseSdk.transferSignals()
            │  {"scam_call_minutes": 4.0}             ┌─────────────────────────────┐
            └────────────────────────────────────────▶ │ POST /api/transfer/check    │
                                                       │ скоринг (XGBoost + SHAP)    │
                                                       │ + граф дропов               │
                                                       │ + звонок ≤ 60 мин → пауза   │
                                                       └──────────────┬──────────────┘
                                   AI-диалог / опекун ◀────────────────┘
```

С телефона в банк уходит **только число минут**. Звук, текст разговора и номер звонящего не передаются.

## Контракт API

`POST /api/transfer/check`

```json
{
  "persona": "client-id",
  "recipient_id": "recipient-id",
  "amount": 20000,
  "lang": "kk",
  "signals": {
    "on_call": false,
    "unknown_caller": false,
    "remote_app": false,
    "session_seconds": 40,
    "scam_call_minutes": 4.0
  }
}
```

- `scam_call_minutes` — минуты с момента, когда Call Guard на этом телефоне отметил звонок как мошеннический
  (уровень HIGH). Нет поля или `null` — такого звонка не было. Учитывается окно **60 минут**.
- Если признак в окне: риск не ниже 0.95, перевод уходит в диалог, первым вопросом идёт «Вам сейчас звонят и
  просят перевести деньги?», в объяснении первым стоит фактор `scam_call`.

Ответ (сокращённо):

```json
{ "tx_id": "TX-1A2B3C", "risk": 0.95, "level": "high", "action": "dialog",
  "factors": [{ "key": "scam_call", "contribution": 5.0, "kk": "…", "ru": "…" }, "…"],
  "message": "…", "question": { "key": "call", "text": "…" } }
```

Тесты: `backend/test_call_signal.py` (4 случая: обычный перевод проходит; перевод родственнику через 5 мин после
звонка ставится на паузу; звонок старше часа не учитывается; в дашборде перевод помечен).

## Android: подключение

1. Модули `android/detector` (чистый Kotlin) и `android/app` (Call Guard). В приложении банка Call Guard
   подключается как модуль; экраны онбординга и разрешений уже есть.
2. Перед отправкой перевода:

```kotlin
val signals = SafePauseSdk.transferSignals(context)          // TransferSignals(scamCallMinutes = 4.0)
body.put("signals", JSONObject(signals.toJson()))           // {"scam_call_minutes":4.0}
```

3. Учебный звонок (кнопка «Проверить на примере») в банк **никогда не передаётся**; SMS опекуну по нему тоже не уходит.

Тесты: `SafePauseSdkTest` (6 случаев), всего в Android 80+ тестов: `./gradlew :detector:test :app:testFullDebugUnitTest`.

## Приватность и согласие

- Прослушивание начинается только после нажатия клиентом «слушать?» в конкретном звонке.
- Распознавание речи — на устройстве (Vosk, казахский и русский). В облако (Claude) по желанию уходит только текст,
  если в настройках задан ключ; для банка это нужно заменить собственной моделью или отключить.
- Текст разговора по умолчанию не сохраняется; хранится время, уровень и причины.
- Перед пилотом нужна оценка юристом банка: согласие на обработку, политика хранения, запись звонков.

## Что предлагаем измерять в пилоте

| Метрика | Как считать |
|---|---|
| Доля переводов после мошеннического звонка, остановленных клиентом | отменённые / все переводы с `scam_call_minutes` |
| Ложные паузы | паузы, после которых клиент подтвердил перевод и жалоб не было |
| Время решения | от паузы до итога диалога |
| Предотвращённый ущерб | сумма отменённых переводов, подтверждённых как мошенничество |
| Охват | клиенты с включённой защитой звонков / активные клиенты Android |

## Что нужно от банка для пилота

- Обезличенная история переводов с метками мошенничества — переобучить скоринг на реальных данных вместо синтетики.
- Список подтверждённых дроп-счетов (из антифрода) — для графа.
- Место в приложении для Call Guard и согласования с юристами и безопасностью.

## Что ещё не проверено

- Работа Call Guard на телефонах (нет эмулятора в среде сборки); чек-лист — `android/DEVICE_TEST.md`.
- Скоринг и граф обучены на **синтетических** данных; цифры качества — не реальная эффективность.
- Детектор звонков проверен на 140 написанных звонках (40 + 100) — тоже синтетика, тот же автор, что и правила.
- iPhone: iOS не даёт приложениям доступ к звуку звонка; там остаётся серверная часть и проверка SMS.
